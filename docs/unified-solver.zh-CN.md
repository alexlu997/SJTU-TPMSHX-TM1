状态：2026-10-13 已授权的目标设计。实现和验收分别记录在任务节点中。

[当前架构说明](architecture.zh-CN.md)继续描述已经交付的行为。

## 1. 范围与决策

- 现有稳态单相模型使用统一的 C++ 求解体系。
- 各流体侧保留独立的物理实现。
- 先改善完整单算例耗时，再扩大批量并行。
- 长算例可以在新进程中从保存的迭代状态继续。
- 0.1 保留 Python 数值参照；0.2 退役数值后端并保留应用接口。
- 保留 macOS arm64 和 Windows x64；0.2 公共执行默认使用 C++。
- 输入、运行、检查点和结果归属同一项目。
- 现有 GUI 输入和结果流程在行为适用时继续保留。

本轮不扩展瞬态和两相方程。
本任务不修改标定系数或原始数据。
新数值方法集中在 C++；接口变化所需的 Python 调用者和文件读取同步更新。
每个实现 PR 均遵循[协作流程](collaboration.zh-CN.md)。

外层物性 Anderson 已退役，物性更新保留原有固定松弛和更新顺序。
`outer_anderson`、`outer_anderson_m`、`outer_anderson_trust`、`outer_anderson_patience` 会在计算前被拒绝，包括显式关闭值。
热方程 Anderson 继续保留。原始设计保留了三种能量算法。
当前守恒 EOS 能量执行使用 T-SOU；H-FOU 和 T-FOU 执行已退役，见第 9 节记录。
完整 3D C API 现在使用 ABI 2；Python 绑定要求与其匹配的原生库。
旧结果仍可读取。检查点仍要求构建身份匹配，不进行跨构建转换。

## 2. 三类独立决策

| 决策 | 记录的含义 | 选择规则 |
| --- | --- | --- |
| 物理模型 | 输运物性、能量关系、压力采样、Nu 与 D-F 关联式、资源和范围 | 显式解析每侧，迁移时保留实际物理含义。 |
| 数值方法 | H/T 未知量、面重构、迭代顺序、线性求解、更新和守恒门槛 | 固定物理定义完成比较，再改变默认值。 |
| 执行策略 | 线程预算、物性求值方法、进度、取消、保存与恢复 | 在认可的数值和物理要求内缩短耗时。 |

`model-h` 使用选定的积分 h(T) 关系；`true-h` 使用选定的 EOS h(T,P) 关系。
统一体系仍明确区分这些物理关系。
H/T 未知量与 FOU/SOU 面格式是另外的数值选择。
当前 model-h SOU 先重构温度再计算 h(T)，true-h SOU 重构焓。
名称中同为 SOU 不代表两者数值等价。

当前同一侧的输运物性和能量物性可能使用不同实现。
例如，true-h 流体组合使用 EOS 能量状态，而空气/水输运保留实际记录的输运模型。
两个实现及各自的压力采样都要记录。
不能仅根据流体名称推断唯一物性实现。

迁移初期，由准备态执行说明显式保存已有路径选择。
N12/N29 再建立通过资格检查、且不依赖另一侧流体的逐流体默认值。
空气/水默认能量关系需要 N08–N11 的比较证据。
新表格近似选定的物理关系，不借此改变物理关系。

### 输入、工作状态与结果

准备态拥有不可变的物理输入、网格、模型资源和解析后的设置。
运行回调与主机路径不属于其持久化物理身份。
运行状态拥有后续迭代会读取的数组和历史。
导出的快照独立拥有数据，不能与活跃写入者共享可变存储。
已发布结果拥有通过验收的证据，或明确标为不合格的完整执行证据。
GUI 草稿修改不会改变该结果的来源。

公共控制器在初次结构迁移时保持现有阶段顺序：

| 路径 | 结构迁移时保留的当前顺序 |
| --- | --- |
| 2D | 初始化；求解两侧流场；准备并求解热场；刷新物性；检查外层收敛；执行必要的末尾更新；细化并收尾。 |
| 3D | 初始化流场；准备并求解热场；保存热证据；检查外层收敛；按需更新物性、流场和压力；收尾。 |

2D 已经并行求解相互独立的 A/B 流场。
3D 已经为每次运行保有独立的流场求解器、物性求值器和热工作空间。
这些能力尚未构成通用线程策略或恢复契约。
移动代码时不附带改变迭代顺序。

### 控制器操作

C++ 控制器提供创建、推进、快照、恢复、收尾和释放操作。
推进操作完成规定工作量后，在明确的安全边界返回。
执行状态区分运行、暂停、取消、失败和完成。
收尾遵循已有的完整结果契约，满足条件后才生成结果。
普通求解入口反复推进同一个控制器。
Python 负责工作调度和快照传递，数值阶段选择仍由 C++ 完成。

C 边界使用不透明运行句柄，新状态传输接口有明确版本。
运行继续推进前，快照数组必须复制到独立拥有的存储。
每个导出所有者有对应的释放操作；借用视图不能超过其所有者寿命。
迁移后，有用的原有单次调用 C 入口使用公共控制器。
这些调用者不保留第二套数值实现。
A03 通过 C 调用者与 Python 绑定确定具体符号和布局。

## 4. 检查点契约

检查点用于继续当前运行，不等于完整 `FieldResult`。
首版恢复要求原生构建、状态格式、物理资源和数值设置匹配。
每个支持的平台分别通过恢复测试。
首版不自动转换跨构建或跨平台检查点。
旧输入文件仍可启动一次使用新合格算法的计算，并生成新的执行记录。

### 必须保存的状态

| 状态组 | 必需内容 |
| --- | --- |
| 身份与布局 | 准备态或精确的本地引用、模型版本、单位、维度、坐标、相位标签、算法和状态格式版本。 |
| 继续位置 | 当前阶段、侧别、网格层级、外层/热/SIMPLE 迭代位置、已消耗预算和下一步操作。 |
| 物理场 | 必要的 T/h、速度、压力与修正、密度、输运系数、边界质量目标和压力锚点。 |
| 收敛状态 | 前一场、更新量；活跃 SIMPLE 调用中的 F2 连续确认次数、停滞窗口和比较快照。 |
| 加速状态 | 必要的热方程 Anderson 样本和重置状态。 |
| 物性迭代状态 | 实际物理实现、输运数组与近似策略。历史检查点还保留原有 HEOS 收尾选择。 |
| 证据 | 已完成的迭代记录，以及分别标识的最后热状态和当前流状态证据。 |

初始源码清单已经定位以下续算状态所有者：

- `full_2d.cpp`：流场/热场、前一温度场、松弛后物性、外层历史与细化位置。
- `full_3d.cpp`：`Runtime` 数组、流场求解器、压力锚点、前一温度场和独立热证据。
- `simple_convergence.hpp`：活跃求解中的 F2 前一速度、连续确认次数与停滞窗口。
- `model_h_common.hpp`：热方程 Anderson 样本队列和重置状态。
- `enthalpy_driver.cpp`：T-SOU 迭代位置、输运数组与加速历史。

根据各恢复边界之后的读取确定完整数组清单。
只有保持约定续算行为时，才能重建矩阵、预条件器与 EOS 对象等派生数据。
不序列化原生指针、回调、线程或对象内存布局。
恢复时不重置已消耗迭代次数和收敛历史。
各字段保留其有限值规则，诊断 NaN 与无效物理场分别处理。

### 保存边界与发布

将完整外层耦合步、完整热迭代块和完整 SIMPLE 步作为候选安全边界。
SIMPLE 步完成必要的密度和边界更新后才能保存。
单元扫掠或线性求解的中间状态不能标为完整迭代步。
记录哪些粗网格初始化必须结束后才能产生首个安全快照。
测量最长安全保存间隔，以及中断后需要重做的计算量。

适用时复用现有 HDF5 类型化数组存储及同目录临时文件发布机制。
增加检查点记录类型和状态格式校验。
只发布完整快照；写入失败后，上一份有效检查点仍须可用。
保存错误与原始执行状态一并报告。
取消与不完整检查点不能替换先前已发布的合格结果。
必须执行进程中断测试；原子重命名本身不构成断电持久性证据。

根据快照实测成本与可能损失的计算量确定定期保存间隔。
只有测量表明确有必要时，才增加异步写入及其额外内存和归属管理。

## 5. 统一质量与性能规则

执行完成、收敛、适用性、指标可用性和设计资格分别记录。
每个结论标明状态来源与定义版本。
最终 SIMPLE 证据与后续更新失败前保存的热证据保持区分。
边界台账不完整不能被解释为残差为零。
保留有符号对流/扩散功率、源项、各相残差和归一化尺度。
2D 保留 W/m 及单位深度流量；3D 保留其实际物理单位。
已有更严格的公式和重放检查继续保留。

已同意的关联式策略检查入口，以及最终场中实际使用关联式的全部局部状态。
每个受限参数最多超出其适用边界 10%。
正值区间 [L,U] 对应允许 [0.9L,1.1U]。
零边界或有符号边界需要明确的领域规则，不能自行设定相对分母。
该比例不是超限单元占比、裁剪规则、EOS 扩展或插值误差预算。
中间观测保留为诊断；最终设计资格使用规定的最终局部求值。
几何、实验来源、相态和硬物性范围约束分别保留。
用户已确认 N06 以原始标定或关联式有效范围作为 10% 的基准。
此前更宽的应用许可不能使超限工况取得设计或优化候选资格。
这些历史结果保留为明确标识的诊断证据。
例如，水侧 HX 标定速度下限为 0.10 m/s，按此规则允许到 0.09 m/s。
此前约 0.014–0.016 m/s 的应用下限不覆盖本次决策。

N08–N11 使用固定模型对照和各主要工况至少三级完整网格，检查以下已接受预算。
现有仅细化热场的 Richardson 流程不能替代完整流场与热场网格加密。
离散、迭代、插值和实验误差分别评估。
实验对照保持固定系数和数据成员。

已接受的工程数值目标如下：

| 量 | 目标 |
| --- | --- |
| 换热量 Q | 0.1% |
| 每侧压降 | 1% |
| 每侧出口温度 | 0.1 K |
| 固体最高温度 | 1 K |

使用物理模型相同的合格细网格参照。
对每个量，合计候选差值、参照网格误差估计和参照迭代敏感性。
在相同单位下，其总和必须满足目标。
相对目标以参照值的绝对值为尺度。
缺少估计的项目仍未解决。网格估计不构成已证明的误差上界。

通过收紧停止容差测量参照迭代敏感性。
温度、Q、压降和总质量流量的敏感性分别最多占第 8 节对应比较限值的 10%。
网格变化和迭代变化的局部场差异单列报告。
整体指标目标不构成完整场的绝对误差上界，也不代表实验精度或改变物理适用范围。
调度或诊断文本变更继续保留已有的精确结果检查。

性能优化先测量完整单算例和各阶段成本。
先复用已有状态复用与共享能量运算，再增加其他机制。
根据瓶颈评估表格插值、减少非线性/线性迭代、工作空间复用及有效并行。
直接 EOS 检查和必要的精确 EOS 收尾计入求解耗时。
并行操作分别拥有可变物性状态。
单算例线程和批量并发使用同一个资源预算。
记录墙钟、CPU 时间、峰值 RSS、初始化、表格以及保存和恢复成本。
区分空缓存、新进程保留缓存和重复热运行。
同时比较相同网格的成本，以及达到相同精度的总成本。
默认值依据合格完整结果选择，物性调用微基准不能单独决定默认值。

## 8. 基线与验收矩阵

冻结 air、water、CO2、sCO2 的全部 16 个有序组合，覆盖两个维度。

CO2-air、sCO2-water、water-air、water-CO2 为 2D/3D 主要成对工况。

显式标记各数值候选，使用通过资格检查的相同物理参照比较。
0.2 仅执行 C++；Python 后端对照保留为历史证据。
不同算法之间不计算后端加速比。

同一离散方程的优化和后端对照保留以下门槛：

| 量 | 比较限值 |
| --- | --- |
| 温度场和出口温度 | 0.01 K |
| Q、压降和总质量流量 | 0.1% |
| 每侧速度最大差值 | `1e-6 m/s + 1e-5 * u_in` |

`u_in` 使用该侧保存的入口速度。
比较时匹配物理输入、网格和停止容差。
保留已有中间场和物理平衡检查。
每个对照结果分别满足其已有物理门槛。
参照迭代研究使用更严格的停止容差，按第 5 节验收整体指标敏感性，并报告局部场差异。

恢复验收包括连续运行与中断运行对照、新进程恢复、多个保存点、预算耗尽和无效状态拒绝。
同时检查写入失败、发布期间进程中断、取消、原始错误保留和 GUI 合格结果不被替换。
迭代顺序或并行改变后，重跑受影响的恢复检查。
测量保存/读取耗时与检查点内存、磁盘成本。
不同浮点执行顺序不要求逐位相等，使用认可的数值标准并记录差异。
