# 协作与任务交接

[中文](collaboration.zh-CN.md) | [English](collaboration.md)

Codex 与 Claude 共用[项目规则](../AGENTS.md)、[运行说明](../README.md)和
[架构约定](architecture.zh-CN.md)。任务决定写入交接记录。聊天的私有上下文
不能代替交接记录。更换负责人或工具后，既有授权和未通过的验收条件继续有效。

Git 操作使用[任务持续授权](../AGENTS.md#1-task-scope-and-authority)。
每项任务仍遵守用户明确提出的范围限制。
对于宽泛目标，先调查并提出方向和验收条件，由用户确认方向后再实现。
方向确定后，自主完成约定工作、旧实现退役和必要验证，不逐步重复请求授权。

## 开始任务

1. 修改任务须明确唯一负责人、允许修改的范围和审查方。每项独立修改任务使用一个
   工作树和一个分支，同一任务的后续工作复用它们。只读工作无需新建工作树。
   同一文件保持一个写入者。每台机器一次运行一项重数值计算；独立轻量任务可以并行。
2. 协调者检查主目录，将干净的 `main` 快进同步，并记录起点提交。遇到本地修改或
   历史分叉时，先保留并检查差异，再决定如何整合。
3. 从该提交建立任务分支，登记工作树和分支。Codex 分支默认使用 `codex/` 前缀；
   用户另有指定时按用户要求命名。
4. 通过任务目录中忽略的 `.venv-path` 选择解释器。共享环境只承载依赖，位于任务
   工作树之外。适用锁文件一致时才能共用。环境相关工作开始前通过
   [环境检查](../AGENTS.md#3-work-setup-and-environment)，仅按该规则复用已通过的检查结果。
5. 项目源码从当前工作树导入。Matplotlib、XDG 和原生物性表缓存放在本工作树
   忽略的 `.cache/` 中。另行记录实际原生库及其源码、构建身份。检查是否仍引用待移除工作树。

## 环境恢复

任务持续授权包含恢复已确定任务所需的环境，也包含在所需环境缺失时创建环境。
恢复依赖该环境的项目工作前，按以下步骤执行：

1. 说明故障、受影响任务、计划修改和恢复方法。记录适用锁、原解释器和指针、
   活动使用方。保留原环境及其源码版本。若不存在可用的旧环境，记录这一限制，
   并保留原有文件。
2. 使用适用的精确锁，在任务工作树之外的最终位置创建替代环境。
   可以用已安装且兼容的主机 Python 创建环境，记录其绝对路径和版本；
   该主机解释器只用于环境创建。安装和恢复检查使用替代环境的绝对解释器。
   这是恢复期间对活动 `.venv-path` 规则的明确例外。
   若没有适用解释器或所需访问权限，报告需要处理的具体事项。
3. 使用替代解释器执行锁检查和 `pip check`，从当前仓库根运行，使用工作树本地缓存。
   完成该环境用途所需的冒烟检查和预热。BO 和桌面打包环境分别使用自己的锁和验收检查。
4. 检查通过后，仅切换受影响且空闲任务的指针。活动使用方继续使用原环境，
   不修改或删除使用中的环境。通过新指针检查该任务；若失败，恢复原指针并保留失败记录。
   只有合规环境才能恢复项目执行。
5. 记录替代环境、检查结果、修改的指针和恢复路径。保留原环境，直到切换验证通过且
   原环境使用方为零。之后移除时仍须通过归档和清理检查。

恢复使用当前锁。依赖版本变更需要独立、范围明确的 PR，同时更新 `pyproject.toml`
和适用锁文件。切换前验证替代环境。日常启动器仍不安装依赖。

## 旧代码完整退役

替换任务在实现前记录新行为和待退役代码。使用任务现有交接记录，详细本地证据
保存在忽略的 `.cache/` 中。

1. 追踪公开和内部调用方、动态名称、CLI/GUI 入口和外部使用方，覆盖配置与历史文件读取、
   导出、打包、测试、夹具和文档。核对实际使用关系；文件名或搜索无命中不足以证明可删除。
2. 按当前使用方需要的行为验证替代实现，保留物理、数据、平台和兼容性要求。
   C++ 数值执行和 Python 应用接口仍属于当前产品能力。
3. 在同一 PR 中迁移使用方和回归覆盖，删除被替代实现及其专属文件。
   同步更新入口、构建清单、配置、导出和文档。保留有效回归覆盖，历史源码使用 Git 保存，
   不在工作目录保留重复的备份文件。
4. 核对残留引用并运行相关使用方和回归检查。每个保留项记录使用方、原因和明确删除条件。
   退役未完成时，分别报告实现与退役状态；任务要求的退役和验证全部通过后才能完成任务。

实现任务中确认的范围外缺陷先记录，交付后按持续授权另开 PR 修复。
每个后续 PR 覆盖已确认缺陷及其必要后果。明确要求只读的任务继续保持只读。

## 同步与审查

1. 负责人完成相关检查，仅提交任务范围内的修改。提交内容不含本地数据、环境和探索报告。
2. 审查针对明确的分支提交，修订由负责人完成。每次增加提交后更新审查结论。
   记录实际审查方，不把代理自查写成人工独立批准。
3. 推送任务分支，创建或更新 PR。简要交接记录放在 PR 描述中；PR 创建前需要交接时，
   使用指定的 issue。本机绝对路径和详细证据保存在本地忽略的记录中。
4. 若 `main` 前进，将当前 `origin/main` 合入任务分支，解决冲突，重跑受影响检查及
   必需 CI，并更新新提交的审查结论。保留分支历史，不强推或覆盖其他负责人的改动。
5. 等待最新 PR 提交的必需 CI。依据持续授权修复任务相关失败，重跑受影响检查，
   并更新修复后的审查结论。范围外的未解决失败须记录下一步处理动作。
6. 必需审查、测试、CI 和仓库保护条件全部满足后合并，不绕过仓库保护。
7. 核对远端合并提交，等待该 `main` 提交的必需 CI 最终结果。若失败，保留失败记录，
   依据同一授权继续修复任务相关问题。
8. 必需 CI 通过后，由协调者将干净的主目录快进至已验收提交，并更新交接记录，
   写明最终提交、CI 结果及剩余验收条件。

任务交付记录须写明每个必需步骤的最终状态。PR CI、合并后主线 CI、桌面验收和
实验验证分别记录结论。

## 交接记录

共享 PR 或 issue 使用以下字段。负责人、范围、审查提交或下一步改变时更新记录。

| 字段 | 必填内容 |
| --- | --- |
| 任务 | 目标、允许修改的模块/文件、授权范围 |
| 人员或工具 | 负责人、审查方、整合协调者 |
| 代码 | 起点提交、分支、当前提交、审查提交、PR |
| 运行条件 | 适用锁、环境用途、原生构建、数据版本 |
| 证据 | 检查项目、对应提交、结果、本地证据记录名称 |
| 状态 | 已完成内容、失败项、未通过的门槛、待批准事项 |
| 下一步 | 具体动作及其负责人 |

本地私有记录补充工作树、解释器、原生库、数据链接目标和证据路径。保留原始失败
和未运行状态。接手方先读共享记录，并核对本机路径，再执行命令。向其他聊天发送
消息需要用户授权该通信。

## 归档与清理

移除工作树前，确认所属任务、写入者和运行进程、未提交或未推送内容、运行资源
使用方及 ignored 证据。在移除范围之外保存必要提交和本地材料，记录原路径、提交、
锁文件、成员清单和链接目标。归档工作树时不跟随原始数据链接。

逐文件核对归档与原件，并实际恢复、读取代表性报告和输入输出文件。现存缺失或
格式损坏单独记录，不改变历史结论。同盘归档不算独立备份；应用的 Git 快照不能
代替 ignored 证据归档。

上述验收通过且活动使用方为零后，才能移除工作树或环境。使用其所属应用或对应的
Git 工作树管理操作。最后处理分支，先确认必要提交有恢复入口。旧筛选结果只归档，
不恢复已退役的求解或优化链；当前多工况 BO 继续作为独立能力维护。

## 工具规则入口

[Codex](https://learn.chatgpt.com/docs/agent-configuration/agents-md) 读取 `AGENTS.md`。
支持 AGENTS 的 [Claude Code](https://code.claude.com/docs/en/memory#agentsmd) 版本在
项目或上层目录没有 `CLAUDE.md` 覆盖该选择时，可以直接读取它。首次接入时在实际
客户端检查规则加载。若既有 Claude 配置需要入口，在 `CLAUDE.md` 中用 `@AGENTS.md`
引用共同规则，不复制出第二套规则。客户端接入和双任务协作试运行分别保留执行证据。
