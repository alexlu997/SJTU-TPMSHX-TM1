# 协作与任务交接

[中文](collaboration.zh-CN.md) | [English](collaboration.md)

Codex 与 Claude 共用[项目规则](../AGENTS.md)、[运行说明](../README.md)和
[架构约定](architecture.zh-CN.md)。任务决定写入交接记录。聊天的私有上下文
不能代替交接记录。更换负责人或工具后，既有授权和未通过的验收条件继续有效。

Git 操作使用[任务持续授权](../AGENTS.md#1-task-scope-and-authority)。
每项任务仍遵守用户明确提出的范围限制。
对于宽泛目标，先调查并提出方向和验收条件，由用户确认方向后再实现。
方向确定后，自主完成约定工作、旧实现退役和必要验证，不逐步重复请求授权。

## 开始任务

1. 修改任务须明确唯一负责人、写入范围和协调者；任务需要审查时，还须明确审查方。用户未另行指定协调者时，
   负责人即协调者。每项独立修改任务使用一个
   工作树和一个分支，同一任务的后续工作复用它们。只读工作无需新建工作树。
   同一文件保持一个写入者。每台机器一次运行一项重数值计算；独立轻量任务可以并行。
2. 协调者检查主检出，将干净的 `main` 快进同步，并记录起点提交。遇到本地修改或
   历史分叉时，先保留并检查差异，再决定如何整合。
3. 从该提交建立任务分支，在[任务状态](#任务状态)文件中登记工作树和分支。Codex 分支默认使用 `codex/` 前缀；
   用户另有指定时按用户要求命名。
4. 通过任务目录中忽略的 `.venv-path` 选择解释器。共享环境只承载依赖，位于任务
   工作树之外。适用锁文件一致时才能共用。环境相关工作开始前通过
   [环境检查](../AGENTS.md#3-work-setup-and-environment)，仅按该规则复用已通过的检查结果。
5. 项目源码从当前工作树导入。Matplotlib、XDG 和原生物性表缓存放在本工作树
   忽略的 `.cache/` 中。另行记录实际原生库及其源码、构建身份。检查是否仍引用待移除工作树。

## 任务状态

任务状态文件向本机的其他任务、工具和后续会话说明当前工作。
它是本地文件，不提交，也不把其中的本机路径复制到 PR。
任务名称为分支名，其中每个 `/` 替换为 `-`。
没有独立分支的任务使用一个简短名称，且不与其他状态文件重名。

1. 开始修改任务或重数值计算前，读取主检出 `.cache/active-tasks/` 中的每个文件。
   `git worktree list --porcelain` 的第一项是主检出。
   不写入其他有状态文件的任务的写入范围。另一任务正在运行重数值计算时，不启动新的重数值计算。
2. 修改任务开始时，在主检出中创建 `.cache/active-tasks/<task>.md`。
   没有状态文件的任务开始重数值计算时，也创建该文件。
   只有任务负责人写入该文件，唯一例外见第 6 步。
3. 在文件中写入以下各行：

   ```text
   Worktree: <absolute path>
   Branch: <branch, or none>
   Owner: <person or tool>
   Write scope: <files or directories>
   Heavy job: yes | no
   State: active | blocked: <reason>
   Next action: <step and its owner>
   ```

4. 重数值计算开始或结束时更新该文件。任务暂停或继续、负责人或工具改变时也更新该文件。
5. 任务收尾时，先更新交接记录，再删除该文件。
6. 若文件所列工作树已不存在，该任务已结束。协调者可以删除该文件，并告知用户。
   若文件因其他原因看似过期，保留该文件并告知用户。

`State:` 行给出任务的简要状态。`Next action:` 行即[交接记录](#交接记录)的“下一步”字段。
任务收尾前，保持这两行为最新。
创建、更新或删除状态文件时，无需进行存储占用测量。
缓存清理时，不删除其他任务的状态文件。
PR 创建前需要由另一台机器继续任务时，使用指定的 issue 承载共享交接。

## 环境恢复

任务持续授权包含恢复已确定任务所需的环境，也包含在所需环境缺失时创建环境。
恢复依赖该环境的项目工作前，按以下步骤执行：

1. 说明故障、受影响任务、计划修改和恢复方法。记录适用锁、原解释器和指针、
   活动使用方。保留原环境及其源码版本。若不存在可用的旧环境，记录这一限制，
   并保留原有文件。
2. 使用适用的精确锁，在任务工作树之外的最终位置创建替代环境。
   可以用已安装且兼容的主机 Python 创建环境，记录其绝对路径和版本；
   该主机解释器只用于环境创建。安装和恢复检查使用替代环境的绝对解释器。
   这是恢复期间对活动 `.venv-path` 规则的明确例外。
   若没有适用解释器或所需访问权限，报告需要处理的具体事项。
3. 使用替代解释器执行锁检查和 `pip check`，从当前仓库根运行，使用工作树本地缓存。
   完成该环境用途所需的冒烟检查和预热。BO 和桌面打包环境分别使用自己的锁和验收检查。
4. 检查通过后，仅切换受影响且空闲任务的指针。活动使用方继续使用原环境，
   不修改或删除使用中的环境。通过新指针检查该任务；若失败，恢复原指针并保留失败记录。
   只有合规环境才能恢复项目执行。
5. 记录替代环境、检查结果、修改的指针和恢复路径。保留原环境，直到切换验证通过且
   原环境使用方为零。之后移除时仍须通过归档和清理检查。

恢复使用当前锁。依赖版本变更需要独立、范围明确的 PR，同时更新 `pyproject.toml`
和适用锁文件。切换前验证替代环境。日常启动器仍不安装依赖。

## 旧代码完整退役

替换或删除任务在实现前记录待退役代码；替换任务还须记录新行为。PR 创建前，该记录写在[本地私有记录](#交接记录)中，
之后写入 PR 描述。详细本地证据保存在忽略的 `.cache/` 中。
其他实现任务在实现前追踪改动可达的使用方。
仅包含相关配置、保存文件、测试、夹具、导出、打包、示例、
GUI 和 CLI 标签、文档、注释和 docstring。
关联修改写在 PR 描述中。
契约指行为、接口、默认值、单位、限值、命令或文件格式。
改动不改变任何契约时，用一句话说明，不列出未修改项。
契约改动记录受影响的契约、更新内容、检查和未决事项。
写明覆盖某一使用方的检查名称。只有将该使用方与改变后的契约进行比较的检查，才算覆盖该使用方。
只固定字面标签的测试不覆盖单位改动。
仅当理由不明显或没有检查覆盖时，才说明未修改使用方的理由。理由相同的使用方合写一句。
交付前完成必要更新。审阅者从需求和差异追踪使用方，再与此记录核对。

1. 追踪公开和内部调用方、动态名称、CLI/GUI 入口和外部使用方，覆盖配置与历史文件读取、
   导出、打包、测试、夹具和文档。核对实际使用关系；`legacy`、`old` 等名称、文件名或搜索无命中都不足以证明可删除。
2. 按当前使用方需要的行为验证替代实现，保留物理、数据、平台和兼容性要求。
   C++ 数值执行和 Python 应用接口仍属于当前产品能力。
3. 在同一 PR 中迁移使用方和回归覆盖，删除被替代实现及其专属文件。
   同步更新入口、构建清单、配置、导出和文档。保留有效回归覆盖，历史源码使用 Git 保存，
   不在工作目录保留重复的备份文件。
4. 核对残留引用并运行相关使用方和回归检查。每个保留项记录使用方、原因和明确删除条件。
   退役未完成时，分别报告实现与退役状态；任务要求的退役和验证全部通过后才能完成任务。

实现任务中确认的范围外缺陷先记录，交付后按持续授权另开 PR 修复。
每个后续 PR 覆盖已确认缺陷及其必要后果。明确要求只读的任务继续保持只读。

探索代码在现有任务记录中写明研究问题、成功标准和采用或退役条件。
只有明确的产品、研究或独立参照用途才能支持其留在主线。
记录使用方和再次评估条件，退役前保存必要结论和未提交证据。
历史结果读取和当前执行是不同约定。保留可读的单位、模型与算法身份、指标定义和有效性状态。
读取要求不自动授权移除仍受支持的恢复或执行接口。
产品或算法改变须先给出证据、选项和推荐，再由用户确定方向。

## 测试范围

新增或修改回归测试时遵守以下规则：

1. 通过转换边界校验后，不再重复组合 `dtype` 或选项。
   在转换边界测试转换，并保留代表性的端到端算例。
2. 仅当测试实际读取临时文件时，才写入临时 JSON、NPZ 或 HDF5 文件。
   C ABI 布局和指针测试写在 `tests/cpp/*_c_smoke.c` 中，不把公开适配层复制为 `ctypes` 镜像测试。
3. 不测试离屏像素坐标、固定边距值或内部 mock 调用次数，也不为已删除符号添加 `ModuleNotFoundError` 测试。
   测试状态变化、物理要求、资源清理和已文档化的契约。

## 同步与审查

第 1–7 步由负责人完成，第 8 步由协调者完成。

1. 负责人完成相关检查，仅提交任务范围内的修改。提交内容不含本地数据、环境和探索报告。
2. 无需用户提醒，主动对明确的分支提交启动一次[独立审查](#独立审查)。
   只修正文档错字、链接或格式的 PR 无需审查；它不得改变任何规则、命令或契约的含义，
   且 `engineering/scripts/check_docs.py` 必须通过。在 PR 中写明这一理由。修订由负责人完成。
   每次增加提交后更新审查结论。
   记录实际审查方，不把代理自查写成人工独立批准。
3. 推送任务分支，创建或更新 PR。简要交接记录放在 PR 描述中。PR 创建前，
   由[任务状态](#任务状态)文件说明任务状态。仅当 PR 创建前需要由另一台机器继续任务时，
   使用指定的 issue。本机绝对路径和详细证据保存在本地忽略的记录中。
4. 若 `main` 前进，将当前 `origin/main` 合入任务分支，解决冲突，重跑受影响检查及
   必需 CI，并更新新提交的审查结论。保留分支历史，不强推或覆盖其他负责人的改动。
5. 等待最新 PR 提交的必需 CI。依据持续授权修复任务相关失败，重跑受影响检查，
   并更新修复后的审查结论。范围外的未解决失败须记录下一步处理动作。
6. 必需审查、测试、CI 和仓库保护条件全部满足后合并，不绕过仓库保护。
7. 核对远端合并提交，等待该 `main` 提交的必需 CI 最终结果。若失败，保留失败记录，
   依据同一授权继续修复任务相关问题。
8. 必需 CI 通过后，由协调者将干净的主检出快进至已验收提交，并更新交接记录，
   写明最终提交、CI 结果及剩余验收条件。

任务交付记录须写明每个必需步骤的最终状态。PR CI、合并后主线 CI、桌面验收和
实验验证分别记录结论。

### 独立审查

使用一位未参与实现、与作者相同模型且不继承作者聊天历史的审阅者。
在 Codex 中，首次通过 `spawn_agent` 并设置 `fork_turns="none"` 启动。
使用前核实当前宿主支持该调用。规则要求负责人主动调用，不会创建文件监视器或技术门禁。
审阅者只读是角色职责，不代表操作系统隔离。

1. 向审阅者提供需求、已接受约束、工作树、基准与待审提交、适用规则和测试证据。
   包含作者的关联修改记录及相关既有决定。审阅者返回前，保持被审工作树不变。
2. 审阅者先从需求和差异独立追踪关联使用方，再与作者的关联修改记录核对。
   阅读相关代码和模型文档，包括动态入口和保存文件使用方，不限于作者的文件清单。
3. 检查关联修改遗漏、无必要代码、重复规则、多余抽象和退役不完整。
   正确性单独检查，包括物理要求、数据、当前使用方和证据覆盖。
   代码相似不足以支持共享。保留必要复制、物理校验、独立测试校验器和有用参照实现。
4. 每条阻止意见提供稳定编号、位置、可达使用方或维护场景、后果和最小改法。
   说明适用的已有证据或最少需要补充的检查。不规定发现数量；风格偏好和无证据猜测不阻止交付。
   首次发现的历史问题不自动属于本次改动。将其列为阻止项前，说明它与当前交付或既有验收的直接关系。
5. 负责人修复意见，或提供保留代码的依据。审阅者核对针对阻止意见的反证。
   非阻止建议需要处理结论，但不单独触发复审。审阅者不编辑文件或写入 Git。
   必要检查由负责人按现有环境和资源规则执行。
6. 第二、第三轮沿用同一审阅者的独立上下文，核对修订、新增影响和未解决意见。
   行为或职责改变时扩展相应检查。不得通过拆分 PR 或重启审阅者重置轮数。
   三轮后仍有实质问题，向用户提交证据与选项；后续改动超出轮数且需要实质复审时也提交决定。
7. 后续提交、同步 main 或解决冲突时，更新覆盖记录。复查受影响部分，不无故重复全量审查。
   复用有效测试证据，没有具体需要不重复重型数值计算。工具不可用或关键证据缺失时保持审查未完成。
   不把作者自查写成独立审查。

维护性各项使用“满足／需修正／证据不足／不适用”，并附简短理由：

- 关联修改完整性。
- 代码必要性和完整退役。
- 重复规则和清晰职责。
- 控制流程和选择是否清楚、有用。

正确性单独报告“未发现阻止问题／存在阻止问题／检查未完成”。未发现问题不证明代码没有缺陷。
交付结论为“可进入后续检查／需修正／需用户决策／审查未完成”。
分项等级不自动决定交付结论；具体阻止项和必要证据决定结论。
分数或轮数上限不豁免现有物理、数据、平台或 CI 要求。实现不得通过降低自身审查要求来取得通过。

初期试运行以普通任务首轮阅读约 2–5 分钟为目标。需要更多工作时记录时间和未覆盖范围，必要数值检查另计。
时间限制不代表自动批准。在三个真实代码任务中验证无需用户提醒的主动调用。
现有任务记录保留有用发现、被反证意见、确认遗漏、时间和轮数。不为凑样本制造改动。
三个任务仅说明初步使用情况，不能推断缺陷检出率。

## 交接记录

单 PR 任务的 PR 描述包含以下内容：

- 改动及其关联修改。
- 检查及对应提交。
- 审查结论及审查提交，或无需审查的理由。
- PR CI 与 `main` CI 结果。
- 未通过的验收条件。

符合以下任一条件时，使用表中全部字段：

- 任务跨越多个 PR 或会话。
- 任务因阻塞暂停。
- 负责人或工具改变。
- 退役未完成。

字段写在 PR 描述中。PR 创建前，字段写在本地私有记录中。
任务状态文件的 `Next action:` 行即其中的“下一步”字段。
“状态”字段记录已完成内容、失败项和待批准事项。
任务收尾前，状态文件与该记录或 PR 描述同步更新。
仅当需要由另一台机器继续任务时，使用指定的 issue。
负责人、范围、审查提交或下一步改变时更新字段。

| 字段 | 必填内容 |
| --- | --- |
| 任务 | 目标、写入范围、授权范围 |
| 人员或工具 | 负责人、审查方、协调者 |
| 代码 | 起点提交、分支、当前提交、审查提交、PR |
| 关联修改 | 受影响的契约和使用方；更新内容和覆盖检查；理由不明显或未经检查的未修改使用方的理由；退役范围和保留理由 |
| 审查 | 审阅者与上下文方式、提交覆盖、意见与处理、轮数、时间和结论 |
| 运行条件 | 适用锁、环境用途、原生构建、数据版本 |
| 证据 | 检查项目、对应提交、结果、本地证据记录名称 |
| 状态 | 已完成内容、失败项、未通过的门槛、待批准事项 |
| 下一步 | 具体动作及其负责人 |

本地私有记录补充工作树、解释器、原生库、数据链接目标和证据路径。任务有本地证据、
使用全部交接字段，或 PR 创建前需要记录时，建立该记录。位置为任务工作树中的
`.cache/<task>/HANDOFF.md`，其中 `<task>` 使用[任务名称](#任务状态)。
保留原始失败和未运行状态。接手方先读共享记录，并核对本机路径，再执行命令。
向其他聊天发送消息需要用户授权该通信。

## 归档与清理

移除工作树前，确认所属任务、写入者和运行进程、未提交或未推送内容、运行资源
使用方及 ignored 证据。在移除范围之外保存必要提交和本地材料，记录原路径、提交、
锁文件、成员清单和链接目标。归档工作树时不跟随原始数据链接。

逐文件核对归档与原件，并实际恢复、读取代表性报告和输入输出文件。现存缺失或
格式损坏单独记录，不改变历史结论。同盘归档不算独立备份；应用的 Git 快照不能
代替 ignored 证据归档。

上述验收通过且活动使用方为零后，才能移除工作树或环境。使用其所属应用或对应的
Git 工作树管理操作。最后处理分支，先确认必要提交有恢复入口。旧筛选结果只归档，
不恢复已退役的求解或优化链；当前多工况 BO 继续作为独立能力维护。

## 存储保留原则

任务写入或清理 TM1 缓存前、任务收尾时和已授权的存储清理期间，均遵守以下规则。目录名为 `.cache/` 不代表其中科研证据可以直接删除。
`git worktree list --porcelain` 的第一项是主检出。`.agents/rules/tm1-local-data.md` 中的相对路径以主检出为起点。
本机设有缓存上限时，在写入或清理 TM1 缓存前测量合计分配占用。
范围包括主检出和各工作树的 `.cache/`，以及上限涵盖的其他 TM1 缓存。同一硬链接文件在这些位置只计一次。符号链接只计自身占用。
任务或清理工作结束时，重新列出当时纳入上限的全部缓存位置。
即使本任务没有删除文件，也要测量这些位置的合计分配占用。

1. 保留原始数据、正在使用的论文与 GCI 证据、选中设计和关键失败样本，以及对应输入、方法、最终场、指标和适用限制。
   保留研究的全部参数、种子、标量观测、约束和原始结论。清理不能把已停止、已否决或未开始的工作改成成功。
2. 中间场和检查点须有明确的分析或续算用途。已结束的软件测试和性能研究不默认永久保留续算状态。
   记录移除的字段、检查点及不再可用的恢复操作。未完成工作保留至所属任务负责人决定其状态。
3. 临时输出可以指定位置时，放在本任务的工作树中。
   验证通过后，在交接前删除本任务的一次性脚本、测试输出、构建产物和可重建缓存。
   保留其他任务、应用程序或留存研究仍需使用的文件。
   保留解释或复现科研证据所需的研究脚本。归档只包含本任务的必要文件，禁止递归归档整个 `.cache/` 或其他任务归档。
   已提交源码从 Git 恢复；大型记录可以无损压缩。
4. 每种活跃用途只保留一个已验收环境：基础、BO、最小后处理。打包或历史环境须注明使用方和删除条件。
   新环境验证、指针检查及零活动使用方确认通过后，退役旧环境。先保存准确包版本、源码版本、依赖锁和独有本地文件。
5. 文件系统属性允许时，共享内容相同的固定快照；保留已保存的相对路径，硬链接不可用时保留独立副本。
   禁止将可变构建输出直接硬链接到证据目录。更新共享文件须整体原子替换，禁止原地覆盖内容。
   移除来源前检查保留结果和代表性恢复路径。
6. 在任务交接记录中说明保留内容、使用方以及删除或复查条件。报告新增、删除、剩余目录占用和卷可用空间的实测变化。
   如果合计占用仍超过本机上限，在同一份交接记录中写明超出量和下一步。
   自动删除限于明确列出的可重建缓存和本任务临时文件。删除科研内容须有已批准的选择范围，不能仅按日期或目录名判断。
