# TM1 执行与自主合并协议

> 本文属于原三模块 Goal 的执行协议。下述“本轮授权”、代理分工和环境新增安排
> 只描述原任务，不能授权后续任务。后续工作遵守当前用户指令与 AGENTS；
> 原始需求、物理与验收门槛继续保留。最终结论见[架构验收](acceptance_architecture.md)。

## 1. 授权边界

用户本轮明确授权：在本 Goal 范围内自行修改代码、提交、推送目标分支、创建/更新 PR、运行 CI、在合规验收后合并。旧 Goal 中“不构成提交授权”“设计完等人工再次批准”不再作为普通停点。

授权不包含：修改仓库管理权限/保护规则、泄露或提交原始本地数据、付费购买服务或许可证、破坏来源不明改动、强推共享分支、绕过 CI、擅自改变物理模型范围、重建正在共享的本地 venv。系统安全策略和当前项目 AGENTS 仍适用。

若框架要求未知物理选项，不用重复询问是否允许普通 commit；只就真实缺失的物理决策提出具体问题，并暂停相应节点。未受影响节点继续。

## 2. 首次启动

读取 AGENTS/README/architecture 和本包；找到实际原始 V0.1 与用户边界。检查现有 Goal/Graph 文件和活动任务，将本计划映射到原有执行方式。不假定 .codex/graph、某个 CLI 参数或额外平台服务存在。

取得默认分支当前 SHA，保存与计划参考 SHA 的关系；记录工作树/分支/脏改动/活动 PR 与任务归属。数据只读并记录 data-revision，不能为了复现实验将原始数据提交到公开仓库。

本地 Python 必须按 .venv-path 与锁文件规则；缺失/失败只暂停依赖该环境的执行。有可用隔离 CI 时按仓库工作流运行。为计划文件或源码静态分析使用工具不等于运行项目环境。不得绕过检查运行数值代码。

新增 HDF5/YAML 依赖由 E00 修改声明和锁，隔离 CI 按流程准备；不把 CI 授权解释为可以改动本地共享环境。没有可用环境就将对应验收标记 blocked_environment。

## 3. 协调者与工作者

协调者独占全局图规格、状态汇总、文件所有权分配、Git 元数据队列与合并队列。工作者只改自己节点文件和自己的 state/证据，不抢写一个共同的 CURRENT_STATUS 或同一份 graph.json。

每个写代码的节点一个隔离 worktree 和分支。创建/删除 worktree、fetch、rebase、合并及共享引用操作交协调者串行处理。不得在他人正在使用的工作树上切分支、reset、清理或覆盖。

没有原生并行能力时按相同 DAG 切换可执行任务，不能声称启动了不存在的 Agent。具备能力时默认最多三个代码工作者；审查可单独角色。重计算默认一个本地作业，CPU/Numba线程/内存/CI配额显式分配。

单个节点原则上对应一个可审查 PR。遇到实际变更过大，应拆成前提明确的子节点和多个 PR，而不是为了保持一个 ID 把所有变化塞进同一提交。拆分只能细化原验收，不能删除验收或把未完成标记 done。

## 4. 调度循环

1. 读取真实节点状态与证据、目标分支状态及当前资源。
2. 依赖未完成的节点不启动需要这些实现的操作；已声明的人工契约样例允许叶节点独立开发。
3. 从拓扑已就绪、资源可用、写范围不冲突的节点中选择；优先选择能解锁更多独立工作且风险可控的任务。
4. 完成实现、节点测试、独立审查、PR 与 CI；CI 等待期间释放重计算资源并调度其他 ready 节点。
5. 阻塞时写入原因、解除条件、受影响后继；仅阻塞相应子图。无关节点继续。
6. 达到合并条件进入串行合并队列；合并后验证并更新 done。
7. 当前会话结束前落盘状态、PR/CI URL、下一动作，供下一活跃会话恢复。不能声称此计划文件自身能够无人值守后台执行。

## 5. 状态机

```text
planned → ready → running → contract_tested → reviewing → ci_pending
   → merge_ready → merged_pending_verification → done
任何适用阶段 → blocked / failed / cancelled
```

`contract_tested` 不代表真实物理验收；`merged_pending_verification` 不代表完成；某个叶节点 done 只代表自身契约承诺，不能据此对外宣布整个平台能力可用。

blocked reason 至少为 dependency、resource、environment、permission、data、contract、physics_scope、ci、file_ownership 之一。状态记录 code/base/HEAD/merge SHA、PR、实际环境、契约版本、审查、测试层级/数量、证据和下一动作。

依赖只认可前置节点的声明验收已完成。若需要并行提前开发但上游实际实现未完成，应通过测试接口/固定样例工作，或新建明确的 contract-only 子节点；禁止把 hard dependency 删除后暗用尚未合并的私有代码。

基础设施重试最多两次；相同失败无新证据不无限重试。测试失败修复需新诊断和新代码/证据，不能通过重复运行凑一次绿色掩盖不稳定性。

## 6. 文件与契约变更

旧大文件的写入者见 GOAL.md。不同 worktree 并不能解决同一文件的语义冲突，因此禁止两个无依赖节点同时承担同一旧大文件的主重构。

需要额外文件或修改公共字段时，工作者在自身请求记录中列出：动机、受影响字段/文件、产生方/消费方、单位/状态/版本变化、受影响节点及迁移测试。协调者安排契约维护者处理，只失效受影响证据。

不准消费者私自增加未记录的 dict 键，不准用外部后端专用字段悄悄改变公共模型。全局 schema 变更可能是多个消费者的真实共同阻塞；必须如实处理，不为了展示并行而隐藏。

## 7. CI 分层与证据

L0 静态：语法/类型/所有权/导入规则；L1 契约：人工数组和模型/端口替身；L2 真实模块/单维度数值；L3 真实文件跨进程；L4 独立物理验证/跨后端验证。每条证据必须标层级和范围。

保留当前平台矩阵、精确锁和 pip check、既有快测试。新增相关集成节点必须跑受影响数值测试，不能被 not slow/not heavy 的排除自动豁免。测试缺少数据、环境、输出字段的 skip 不构成该项通过。

必需 CI 检查要在节点 PR 描述中列出，针对精确当前 PR HEAD 获取关联运行和结论。PR 工作流若实际检出 refs/pull/<n>/merge，必须另记 tested_candidate_sha、tested_base_sha、source_head_sha；不能把测试合并候选的 SHA 与源码 HEAD 混为一谈，也不能使用旧候选的绿色检查。没有 workflow、combined status 为空、job未启动、timeout、cancelled 都不能当 green。已有测试失败要区分基线问题与新回归，不可直接关测试。

CI 队列按 PR/分支隔离；cancel-in-progress 只能有明确的同一 PR 被新 HEAD 取代理由，不能取消其他节点或用户任务。保持矩阵 fail-fast=false。重计算预算显式限制，避免同时启动多个各占满线程的仿真。

## 8. 自主 PR 与合并门槛

普通代码节点依次满足：

1. 修改属于节点所有权，工作区无混入他人改动；图中真实依赖完成。
2. 节点验收证据齐备，单位/坐标/模型/收敛/警告及原始数据边界未改变；所有物理修正有独立明确范围。
3. 独立审查角色读取真实 diff 和测试证据，没有未解决的阻塞问题。内部 Agent 审查报告不冒充 GitHub 法定审批；若仓库要求某种正式审批，必须实际满足。
4. 当前精确 PR HEAD 的既有与节点必需 CI 全部成功；要求的真实测试不为 skipped/not-run。
5. 目标分支未脱离已测试的基线，或平台已经对最新 base 的合并候选执行并通过检查。目标分支改变则更新并重验受影响范围。一个 PR 检查为绿色不能证明它与另一个并列 PR 的组合已经验证。
6. 合并协调者串行执行正常合并，不强推、不使用绕过管理员选项、不修改保护以强行过关。
7. 记录 merge SHA，核对合并后的目标分支检查及必要冒烟。失败则保持 merged_pending_verification/failed，暂停相关后继激活，创建针对本 Goal 的修复或 revert PR，不 reset/强推历史。

共享锁/模型/schema 后来变更时，将受影响已完成节点记为需要复验，保存旧证据而非删除历史；不能因为曾经 done 就永久信任旧运行。

GitHub 原生 auto-merge 只有在仓库配置支持时使用；原生 merge queue 存在则按队列验证，并配置 merge_group 触发。不能假定仓库已开启这些能力。没有队列时由单一协调者串行更新 base、验证候选、再合并；若存在外部并发合并且无法确认候选与实际目标一致，不宣称原子安全，暂停该 PR 的合并而非停止其他开发。

本计划不授权修改仓库管理员权限。若分支保护/正式审批/平台权限阻止合并，记录具体阻塞；一般本地实现和其他节点可以继续。已经失败的数值验证不能借用户授权绕过。

## 9. 主分支保持可用与回退

允许合并完整但未接入生产默认路径的叶实现。禁止在公共 API 下挂上测试替身、pass 方法、虚构成功返回值或悄悄重跑旧全流程的适配器。

生产路由切换在维度/应用集成 PR 发生。每批可独立验证和 revert；不要将整库整理作为单次不可回退的大搬迁。旧兼容入口只单向委托，不长期保留第二套生产公式。

回退只针对本 Goal 自己引入的变更，使用可审查的 revert/修复 PR 并运行 CI。不要撤销用户其他工作或删除用户分支。发现原始数据有问题时不得为通过测试自动改记录。

## 10. 每轮汇报格式

报告实际新增完成节点、已合并 PR/提交、运行的测试及范围、正在等待的 CI、阻塞节点/原因/影响范围，以及下一轮 ready 节点。不用“整体完成80%”掩盖某个关键交接还没有真实运行。

最终分别报告 M-A、M-B。不能把一堆叶节点 contract_tested 汇总成真实跨进程完成；原文需要的能力未交付时继续明确列出。
