# 两处交接的实现蓝图（G10 的设计输入，不是现有已实现 API）

## A. 最小契约先行，而不是等全项目设计完

G10 发布公共类型、入口语义、字段含义和人工小样例，不负责一次完成所有 HDF5、所有后端、所有指标与所有长算例。HDF5/YAML 由 D10/D20 完成，扩展指标由 H30 完成，真实基线由 B20/B30/B40 完成。

这样消费者可以在真实上游尚未接线时使用同一规格开发。人工样例标记 synthetic，不是验证数据。生产模块不返回测试替身结果；未实现能力显式拒绝。

以下字段组是实现建议。实施时优先复用既有 ComputeConfig，不建立两个值来源。每个字段需写原始代码来源、产生方、消费方、单位、shape、可选条件、模型适用域与版本规则。

## B. CaseData：前处理到求解

| 组 | 必须表达 | 注意事项 |
|---|---|---|
| 身份与版本 | case_id、schema_version、准备工具/模型版本 | 文档版本与数据 schema 版本不同 |
| 配置快照 | 用户输入与解析后实际设置 | 环境变量覆盖解析/记录一次，求解阶段不能悄悄再覆盖物理输入 |
| 物理域 | 宏观尺寸、A/B/固体区域、参考深度 | 2D 的每单位深度与3D整机量不能同名混用 |
| 物理网格 | 实际坐标/间距/拓扑与边界标签 | 局部开口必须在最终实际网格上确定；后端只重排索引 |
| 设计场 | 拓扑、L/t/孔隙率及来源 | 独立变量与派生量一致；现有挤出场不宣称任意3D场支持 |
| 固定闭合 | K/cF、几何面积/单侧孔隙率等或明确资源 | 基准参数与实验有效修正分开；修正只施加一次 |
| 运行时模型 | 物性/换热闭合的名称、版本、参数、资源、适用域 | 不序列化函数、lambda或依赖前处理存活的对象 |
| 边界与初值 | 入口类型、流量/速度定义、压力基准、温度、初场 | 表压/绝对压、开口面积、单位法向与流向明确 |
| 数值与输出 | 模型模式、迭代预算、输出需求 | 筛选/验证不同；不能用某后端私有选项改变公共物理定义 |

CaseData 提交后只读。dataclass frozen 并不保护其中的 numpy 数组或字典，必须通过不可变表示、数组只读或求解工作副本实现隔离并测试。运行期间的温度、压力、局部物性和矩阵缓存只属于 Solver RuntimeState。

前处理可以交付确定的实际网格，也可以交付能唯一确定网格的定义；若采用后者，解析后实际网格必须随运行证据记录且与前处理定义一致。不要把求解器根据预算又选另一套分辨率称为格式适配。

进度回调和取消令牌是运行控制参数，不属于可持久化的物理算例。模型资源可嵌入或固定版本引用，但接收进程必须可解析，不能只记录开发者电脑临时绝对路径。

## C. FieldResult：求解到后处理

| 组 | 必须表达 | 为什么不能省略 |
|---|---|---|
| 来源 | result_id、case_id、backend_id/version、code/data/model revision | 结果可追溯，不依赖现时界面草稿 |
| 原生网格 | 坐标、连接关系、区域、边界及字段位置 | 不能把单元中心值误当面值 |
| 原始场 | A/B/固体温度、压力、速度及声明输出 | 显示平滑和 Richardson 外推场另存、另标识 |
| 通量证据 | 已含面积的带符号面质量流量、能量输运证据 | 不能从一个总流量虚构每个面数据，不能重复乘面积/孔隙率 |
| 压差证据 | 参考面/提取规则、所需面压力或外推数据 | 保持既有 face-extrap 等口径，不仅复制一个 ΔP 标量 |
| 物性/闭合 | 后处理所需已评估字段或独立可读资源 | 正式后处理不能回读活动求解器或重新运行其私有函数 |
| 状态时间点 | last_main_thermal、final_report、display、refined 等明确区分 | 不混用不同次求解的温度、压力与通量 |
| 运行判断 | execution status、convergence、physical applicability、warnings、screening/validation | finished 不等于converged，也不等于物理已验收 |
| 辅助量 | 离散/通量/模型定义版本、必要算例快照 | 同一结果可以在另一个进程正确解释 |

首轮反向分析当前指标所需数据，再确定最小输出。不是保存全部 solver.__dict__，也不是只存 Q、ΔP、Tout 摘要。当前没有足够证据支持的额外指标必须返回 insufficient_data，而不是隐式重跑。

### 必须保留 PR #93 的新口径

二维出口温度的报告基准是“最后主热求解原始温度 + 对应面质量流量 + 真正开口”。使用正向外流质量作权重；不额外乘 cp 或面积。原始带符号流量不能被裁剪或原地覆盖，因为守恒诊断仍需要回流等信息。没有有限的正向外流质量时保持明确错误。

三维现有报告与热求解的状态/压力锚点可能分别记录。不能在迁移中自动认定它们完全一样；必须保留来源并用当前基线回归。正式指标所用离散证据与在线监控证据分别标识。

## D. PerformanceResult 与 MetricSpec

PerformanceResult 保存数值、单位、定义版本、来源结果、适用性、有效性/精度等级和不可计算原因。不要把求解未收敛改成后处理“成功即有效”。

MetricSpec 说明压差测量范围与平均方式、Q 报告侧与正负号、二维/三维归一化、Tout 的口径，以及 h/f/PEC 等所需参考定义。V0.1 没有给出所有这些物理选择；已有代码明确的先复用，新增歧义交 H30，不能让该歧义冻结全部基础字段。

优化目标组合、符号转换、惩罚策略留在应用侧。缺数据时返回状态，不填0；误将 W/m 当W或kg/m当kg须被测试发现。

## E. 三模块公开入口与接口注入

目标职责（签名最终由 G10 冻结）：

```python
case = preprocessor.build(config)
result = solver.run(case, backend="python", control=run_control)
performance = postprocessor.evaluate(result, metric_spec)
```

为并行开发，可以在构造具体实现时注入同一公共协议的模型目录或运行端口：测试传入 tests 中的替身，生产由集成层注入真实实现。这不是允许用户修改内核；是明确的公共依赖接口。

共同工作流负责绑定和顺序调用。前处理/求解/后处理之间没有私有导入；公共数据、模型资源和只接收数据的共享纯函数可以共用，不形成第四个隐藏流水线。

求解器能力表对维度、网格、模型、流体、设计场、边界、输出和取消机制声明实际支持。C++/OpenFOAM 未实现时不能填 true，更不能自动回退 Python。

## F. 文件契约

V0.1 原清单：case.yaml、case.h5、results.h5、results.vtk、metrics.json。新增交换契约统一SI，旧明确 *_mm 字段通过唯一边界转换；保存 schema_version。既有叶内核仍要求 mm 参数时，以具名适配显式 m→mm 转换并在迁移清单中登记，不将内部全部 SI 的原文要求悄悄缩减为仅文件 SI。M-B 对剩余内部单位迁移独立核对与验证，不能以删除 *_mm 后缀伪造单位统一。

HDF5 中数组、元数据和资源位置明确；不将 Python pickle/object dtype 的任意对象作为协议。YAML 安全解析，不执行构造器。版本未知、必选字段缺失、shape不匹配、资源不可解析均给出明确错误。

D10/D20 可用 G10 人工样例开发。V20/V30 必须使用真实算例做三进程交接；两类证据不能混淆。

## G. 契约测试与模型回归的关系

人工数据能够证明字段、公式、顺序和错误行为；真实小算例证明模块已接线；多进程/最小依赖证明真正独立；原始数据或可信参考的物理验证证明适用精度。任何一层都不能代替其他层。对当前尚未验证的物理模式，只能保持已声明限制，不能因重构回归一致而自动获得物理认证。
