## 2. 总目标与两个里程碑

**总目标：**把现有计算能力整理为可独立维护、分别运行的前处理、求解、后处理，通过版本化 CaseData 与 FieldResult 交接；让现有和未来的应用只依赖公开 API。保留现有物理模型、闭合、离散、状态检查和指标语义，避免以“重构”掩盖模型变更。

**M-A：现有 Python 架构交付。**涵盖三模块独立化、两处交接、YAML/HDF5/指标 JSON 和可视化交付、现有应用接线、现有支持能力及错误路径、最小依赖与真实多进程验收。由 Z00 收口。37 个核心节点。

**M-B：原文能力交付。**在 M-A 之外，继续跟踪真实 C++、OpenFOAM、扩展指标、其他物性提供器，以及原文“逐步／可扩展／必要时／仅预留”的能力。由 Z10 按原有限定收口。8 个能力分支节点（包含收口）。未实现或被环境/物理选择阻塞的项目不可勾选完成。

M-A 可以先完成并使用，不因 REFPROP 许可、OpenFOAM 环境或尚未明确的 PEC 基准而全部停工。M-A 完成不能被描述成 V0.1 全功能完成。拓扑优化第一阶段仍仅保留梯度/伴随接口，不强行实现伴随求解。

## 4. 两处交接与依赖方向

```text
应用/工作流
  config → 前处理 → CaseData → 求解 → FieldResult → 后处理 → PerformanceResult
                               └─ Python / C++ / OpenFOAM
```

CaseData 是准备好的计算问题，不是原始配置换名。它包含已确定的物理网格、区域、设计场、模型资源、边界和实际设置。前处理关闭以后，求解侧不再需要其局部变量、函数闭包或对象。

FieldResult 是足够重建约定指标的证据包，不只是几项 Q/ΔP 摘要。它包含原生网格和场位置、场、边界/测量通量、明确的状态时间点、运行判定和必要模型资源。求解退出后，后处理不访问求解器私有实例，也不为缺数据自动重算。

同进程可以直接传递对象，不强制每次落盘；分进程通过 V0.1 的 case.yaml、case.h5、results.h5、results.vtk、metrics.json 交接。正式 I/O 验收不能以临时 JSON/NPZ 代替 HDF5。

源码依赖方向不是数据箭头：前处理不导入求解执行器；求解不导入前处理/正式后处理；后处理不导入活动求解器。工作流才是三者的共同调用者。domain、纯模型/资源和必要共享纯函数是技术支撑，不是第四个业务大模块。

实现建议保留 sjtu_tpmshx、domain、solvers 包名，新增 preprocess/postprocess。G10 先冻结公共类型和接口，模型支撑保持后端无关。目录按真实职责逐步迁移，不先全库改名。

## 5. 为什么不能把全部节点都画成无依赖

真实依赖无法删除：没有正确的面通量，后处理不可能证明真实 Q；没有读写实现，不可能完成三进程文件验收；未确认的物理模型不能靠假数据验收。计划采用的是：

**少量公共基础 → 大量并行叶节点 → 分维度/分应用集成 → 最终收口。**

开发的串行等待被压缩，而不是把必需依赖伪装成不存在。某节点失败只阻塞它的必需后继；无关兄弟节点继续。一个必需集成节点受阻，最终里程碑仍然不能完成，这不是调度失败，而是正确的质量边界。

### 两层验收保证并行不失真

叶节点先对公共类型、接口和固定人工样例开发。测试提供器、固定场和假运行端口只存在于 tests，允许后处理或应用适配不必等真实求解器。

叶节点完成表示“它自己承诺的实现与契约测试完成”，不表示真实集成完成。只有 I20/I30/I40/V20/V30 等节点有资格提供真实链路验收。生产运行不允许默认落到测试替身、空后端或隐式旧流水线。

未被生产路由激活、完整实现且独立测试通过的叶模块可以按门槛合并；不是允许把 pass/TODO 骨架或未经测试的半成品合并。激活生产路由必须等真实集成证据。

## 7. 并行的关键不是 Agent 数量，而是文件所有权

同一个旧大文件不能让多个 Agent 同时重写。计划故意让 P、S、R、H、A 叶节点优先写新职责目录，对旧源码只读：

- 旧 stages_2d.py/solve_2d.py：I20 独占。
- 旧 stages_3d.py/run_stack_3d*.py/grid_3d.py/flux_3d.py：I30 独占。
- 公共契约：G10 所有者；后续变更经同一维护者定向修改，不由消费者各自加字段。
- controllers/compute_pipeline.py 和公开 api.py：I51 所有者。
- main.py 与既有 UI mixins：I52 所有者。
- 旧优化 evaluator/core evaluator：I53 所有者。
- 旧设计 forward/sizing/CLI：I54 所有者。
- 旧模型模块及 solvers/__init__.py：I55 所有者。
- CLI 顶层命令：I56 所有者。
- pyproject、锁文件、CI：E00 所有者；后续追加变更继续通过该维护者的小任务，不由各工作节点抢写。

所有权控制不是禁止别人阅读，也不是保证 Git 自动合并一定无冲突。语义冲突仍需集成检查。确需同文件修改时，申请明确原子子任务和串行写入，不依赖“改了不同几行”来保证安全。

## 8. 调度与故障隔离

推荐一个协调者、最多三个代码工作节点、一个独立审查角色。角色不一定等于永远在线的独立进程；只有实际启动才称“并行 Agent”。重数值本地作业先限一个，之后按测得资源调整；不要三个 Agent 各自占满全部 Numba 线程。

节点只有两类前置：hard dependencies 和资源。接口未定、真实上游结果缺失等是依赖；权限、环境、数据、CPU、外部后端是资源或范围阻塞。具体状态见 OPERATIONS.md。

例：OpenFOAM 环境缺失仅阻塞 X21/X22 和 M-B 的最终完成。D20 阻塞会影响 V20/V30 的文件验证，但 H10 可以继续用内存人工数据工作，I20/I30也能先完成内存真实链路。B30 的长算例失败会阻止 I30 的真实验收，不要求 P20/H10/A30 停止。

某个发现证明公共契约或模型基础不成立时，影响可能是全体消费者；这类真实公共阻塞不能人为隐藏。修订契约要列 affected_nodes，只失效受影响证据，不清空已验证的无关工作。

共享环境被意外修改、来源不明数据将被覆盖、凭据泄露等可成为资源级或全局安全暂停；与普通单节点失败区别处理。

## 9. 必须保留的工程与物理边界

本轮重构不更改：总/单侧孔隙率分配、孔隙内/表观速度、质量流量/质量通量、绝对/表压力、实际网格/端口、壁面离散、D–F基准/修正次数、Nu选择、热状态与通量、二维单位深度、既有收敛和无效判定。

前处理不把状态相关物性和 Nu/h_v 冻结；求解不在运行时重新解释 CaseData 的物理网格；后处理不从显示速度重建本来应该交付的面通量。指标需要的新字段由契约变更提供，不猜测或静默回退。

原文的 h/Re/Nu/f/PEC 要明确测量与参考口径。已有定义可复用，未定义的物理选择只挂起相关指标，不能用随意公式将清单填满。

新增几何、各向异性、物性后端或数值修正是独立模型节点。测试替身和跨后端一致性均不能替代独立物理验证。

## 10. 自动提交、PR、CI 与合并

执行者按照 OPERATIONS.md 在隔离工作树、独立分支上提交并提 PR。合并只由单一协调者执行，检查对应精确 HEAD 的 CI、节点验收、审查和最新目标分支兼容性。普通授权内步骤不逐次询问用户。

不能为通过 CI 删除测试、扩大容差、伪造 fixture、取消别人的测试、关闭分支保护或强制推送共享分支。任何测试未运行都如实记录，不把 skip 当 required evidence。

已获得合并授权不等于运行环境已经具备令牌或平台权限。权限缺失时只阻塞相应发布/合并节点；可以继续有权限的实现、静态分析或测试，不能无限重复无效请求。

## 11. 完成标准

M-A 完成必须有：真实前处理独立；真实求解独立；真实后处理在无数值后端环境独立；内存/文件链路一致；实际已有能力和拒绝路径覆盖；外部参数/设计场/设计软件仅使用公开接口；正式指标/状态/元数据正确；现有CI及对应真实回归通过；代码和文档当前状态一致。

一个小算例贯通、三个目录存在、mock测试通过、PR已经合并，都不能单独等同于 M-A 完成。

M-B 保持 V0.1 的分期语义。未交付的后端/物性/指标继续保留真实状态，不为了“完成 Goal”删掉要求。

## 12. 本包怎么使用

将整个目录提供给 Codex，先读 START_HERE.md，再读本文件、OPERATIONS.md、CONTRACT_BLUEPRINT.md、REQUIREMENTS.md、graph.json 及需要的节点卡。graph.json 是项目级任务图，不是声称 Codex 有一条原生的 graph 导入命令。有既有 Graph 执行器则映射本图，无则由当前 Codex 会话协调节点和工作树；工具不具备并行子代理时，保持相同图与状态进行可切换的顺序执行，不虚报并发。

`tools/check_graph.py` 仅校验计划结构、列依赖与拓扑就绪节点，不自动修改仓库、启动 Agent 或调用 GitHub。它不是后台调度服务。

节点当前均 planned；执行时将真实证据写入状态文件。主文档提供策略，graph.json 提供机器可读节点和依赖，节点卡提供细节。发生规格变更由协调者同步更新，不能多套状态彼此矛盾。
